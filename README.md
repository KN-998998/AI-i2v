# AI 餐饮引流视频工作台

面向餐饮品牌的竖版短视频本地生产工作台。它把菜品图处理成图生视频首帧、生成短视频片段，再批量组合成多条 9:16 成片，并在时间线上加入 BGM、TTS 人声和同步画面文字，产出可直接发布的引流视频。

工作台以**流程画布**串联全局，并提供**分步操作页面**完成每一步业务编辑。画布负责查看和连接流程节点；图片处理、片段生成、成片合成和声音文字等具体工作在对应页面完成。另有面向素材库的批量建稿与人工整理工具。

设计目标是让运营/品牌人员独立完成从素材到成片的整条流水线，系统只做推荐与自动化，不替代品牌判断——菜品图、背景模板、提示词动作和最终片段组合均需人工确认。

## 页面总览

| 页面 | 路径 | 主要职责 |
| --- | --- | --- |
| 流程画布 | `/canvas-mvp` | 节点增删、拖拽、自动布局、连线和分步入口；核心节点不可删除 |
| 素材与菜品 | `/workflow/assets` | 上传菜品图，维护菜名、分类、冷热与主体类型；内嵌“素材库批量建稿” |
| 素材库人工整理 | `/workflow/asset-library-review` | 从素材库扫描/上传菜品图，人工确认分类后整理归入 `分类/菜品/图片` 目录 |
| 图片处理 | `/workflow/image-processing` | 腾讯云 GoodsMatting 抠图、背景模板、主体位置与 9:16 首帧合成 |
| 提示词装配 | `/workflow/prompts` | 每个节点独立编辑 L0/L1/L2、镜头、景别与动作，并预览提示词 |
| 生成视频片段 | `/workflow/generator` | 创建 Kling 任务、查看状态、恢复未完成任务、按素材管理片段版本 |
| 成片合成 | `/workflow/compose` | 候选片段池、按片段裁剪精彩区间、批量生成多套无声成片方案 |

## 生产流程

主链路由七个分步页面串联，素材库工具是第 1 步之前/之上的备选入口，与手工路径共用同一套画布草稿与片段库：

```text
（可选）素材库人工整理 —— 把零散菜品图归入 分类/菜品/图片 目录
                │
                ▼
素材与菜品 ——(单图手工 / 素材库批量建稿)→ 图片处理 → 提示词装配
   │  ▲                                            │
   └──┘(批量建稿“应用到画布”在此创建节点)
                                                    ▼
                                               生成视频片段
                                                    │
                                         成片合成（多工作区·批量）
                                                    │
                                               声音与文字
                                                    │
                                               成片结果
```

### 分步说明

1. **素材与菜品** — 单张维护：上传菜品图并填写菜名、分类、冷热属性、主体类型（菜品主体 / 手部 / 厨师上半身 / 手部+厨师上半身）。批量建稿：给定素材库文件夹与各分类期望数量，自动扫描并按“菜品文件夹名”去重、抽图与挑背景，先生成待确认流程，再决定是否调用抠图和 Kling。
2. **图片处理** — 菜品主体调用腾讯云 GoodsMatting 抠出菜品，与本地背景模板合成为视频首帧；手部/厨师等人物素材自动跳过抠图并保留原图。原图永不被覆盖，处理图单独保存、可重复生成。背景模板可上传复用，处理时裁为 9:16 并做虚化压暗。
3. **提示词装配** — 槽位化提示词：L0 画面元素、L1 主体、L2 次级动态（最多 2 项，一条 3 秒切片只有一个镜头动作）。每个提示词节点独立编辑并预览最终文案。
4. **生成视频片段** — 按节点发起 Kling 图生视频（默认 3 秒、1080p、9:16、无声），任务落盘、后台轮询并自动下载到本地片段库。同一素材每次生成会保留为 V1、V2… 版本；选择“当前使用”版本后才会进入成片合成候选池。
5. **成片合成** — 设置批量数量 × 每条片段数后“智能推荐方案”或“随机生成方案”，在每条方案时间轴中拖拽片段、调整源入点/出点并确认裁剪；运行预检后逐条或批量生成**无声成片**。推荐会考虑片段质量与菜品多样性，甜品/水果最多保留一段且置于末尾。
6. **声音与文字** — 在无声成片基础上配置 BGM（页面上传）、TTS 人声与多轨画面文字，拖动时间块并生成最终**有声成片**。
7. **成片结果** — 查看每条方案的无声（检查顺序）与有声（用于发布）结果；需要修改声音或文字时返回第 6 步。

## 核心规则

- **草稿按浏览器隔离**：首次访问的浏览器会自动生成独立草稿 ID 并保存在浏览器本地存储中，同一浏览器内共享一份画布。草稿变更后自动保存（约 0.8s 防抖），也可手动保存；片段库每 30 秒自动扫描同步。
- **生成片段统一存放**：真实 MP4 存于 `output/canvas_clips/`，浏览器兼容的代理预览与缩略图位于其下的 `.previews/`、`.thumbnails/`；草稿与任务状态存于 `output/canvas_drafts/<draft_id>/`。
- **Kling 任务可恢复**：任务取得 `task_id` 后即落盘，后端重启时会重新轮询 `queued`/`running` 任务，并在完成后自动下载到片段库。
- **片段版本化**：每个素材可对应多个生成版本，确认“当前使用”后合成默认采用该版本；运营仍可切换回历史版本或重新生成。未绑定生成节点的历史本地文件仅可浏览，不进入候选池。
- **质量分数为本地提示**：分数来自本地规则（画幅、时长、帧率、分辨率、编码），只用于排序与预检提示，不是模型训练评分。合成前预检会报错或提示（如时长、完整性、文字/人声数量）。
- **批量合成为多工作区**：支持同时维护多条成片方案；单个方案失败不会覆盖其他方案的成片。裁剪确认会被记住并可复用。
- **文字与人声共用文案**：画面文字与 TTS 人声同源于拆分后的文案段落，可相互同步拖动。TTS 合成后按实际音频时长回写文字/人声轨道；旧草稿文本在读取时自动兼容修复。
- **画面文字支持多轨**：可重叠、跨时间范围、拖拽与改时间；支持字体、字号、颜色、描边、背景框与打字机效果；位置可选上方品牌区 / 中上钩子区 / 画面中央 / 底部安全区 / 自定义。
- **人工在环**：菜品图、背景模板、提示词动作和最终片段组合仍需运营确认；素材库分类可用规则记忆 + 本地回退 + Qwen 辅助识别，但以人工确认为准。

## 技术栈

- **前端**：React 19 · TypeScript · Vite · @xyflow/react（React Flow）· zustand
- **后端**：Python 3.11 · FastAPI · Uvicorn
- **媒体处理**：ffmpeg / ffprobe · Pillow · OpenCV
- **外部能力**：可灵 Kling（`kling-3.0-omni` 图生视频）· 腾讯云数据万象 GoodsMatting 抠图 · 阿里云百炼 Qwen TTS / LLM（文案拆分、菜品分类辅助）

## 快速开始

### 环境要求

- Windows 10+，Python 3.11（推荐项目 Conda `PY3_11` 环境）
- Node.js（前端构建使用 `npm.cmd`）
- `ffmpeg` 与 `ffprobe` 已加入 PATH（用于片段代理预览与成片渲染）

### 1. 安装依赖

```bat
python -m pip install -r requirements.txt
cd frontend
npm.cmd install
cd ..
```

### 2. 配置 `.env`

```bat
copy .env.example .env
```

| 能力 | 配置 |
| --- | --- |
| Kling 图生视频 | `KLING_API_KEY`，或 `KLING_ACCESS_KEY` 与 `KLING_SECRET_KEY`；可选 `KLING_BASE_URL`、`KLING_MODEL` |
| 商品抠图 | `BACKGROUND_REMOVAL_PROVIDER=tencent`、腾讯云 `TENCENTCLOUD_SECRET_ID/SECRET_KEY`、`TENCENT_COS_BUCKET`、`TENCENT_COS_MODEL=GoodsMatting` |
| Qwen TTS | `TTS_PROVIDER=qwen`、`QWEN_API_KEY` 或 `DASHSCOPE_API_KEY`、TTS 模型与音色；支持音色复刻（`QWEN_TTS_CLONED_VOICES`） |
| Qwen LLM（可选） | `QWEN_LLM_ENABLED=true`：文案智能拆分、素材库菜品分类辅助，复用 `QWEN_API_KEY` |
| BGM | 无需密钥，在“声音与文字”页面上传音频文件 |

`.env`、素材、视频、草稿、日志与构建产物均被 Git 忽略，不会提交远程仓库。

### 3. 启动工作台

双击根目录 `start_dev.bat`：

- 脚本会结束占用 `8015` 端口的旧服务，构建前端，启动 FastAPI 并自动打开
  `http://127.0.0.1:8015/canvas-mvp`。
- 后端启用 reload：修改 `web/`、`pipeline/` 下 Python 后刷新浏览器即可；修改 `frontend/` 后重新运行一次 `start_dev.bat`（或手动执行 `scripts\build_frontend.bat`）。
- API 交互文档位于 `http://127.0.0.1:8015/docs`。

### 4. 全量验证

```bat
scripts\verify.bat
```

该脚本先构建前端，再执行前端模型测试与 Python 测试（`pytest`）。

## 本地数据目录

```text
output/
├── background_templates/          # 可复用的背景模板
├── canvas_clips/                  # 生成或导入的视频片段
│   ├── .previews/                 # 浏览器兼容的本地代理预览
│   └── .thumbnails/               # 片段缩略图
├── canvas_drafts/
│   └── <draft_id>/                # 每个浏览器一份草稿
│       ├── draft.json             # 节点、连线、片段与多工作区状态
│       ├── files/                 # 上传的菜品图、尾帧、BGM 等
│       ├── generate-*.json        # 可恢复的 Kling 任务状态
│       └── compositions/          # 无声/最终成片与任务记录
├── asset_library_manual_review/   # 人工整理任务的扫描清单与中间态
└── canvas_asset_category_rules.json  # 菜品分类的已确认规则记忆
```

刷新浏览器后，节点、连线、素材引用、多合成工作区与轨道配置会从草稿恢复；当前正在生成/抠图/合成的任务由后端在重启时接管。

## 工程结构

```text
frontend/                 # React / TypeScript / React Flow 页面、状态与模型测试
  └── src/components/      # 各分步页与画布交互组件

  ├── api/routes.py        # HTTP 路由与请求校验
  ├── services/            # 草稿、素材库、抠图、生成、合成、质量等业务服务
  └── core/                # 应用配置与日志

08_技术方案/              # 提示词与图生视频装配方案
```

前端构建产物写入 `web/static/canvas-app/` 并由 FastAPI 提供，该目录可再生、不提交 Git。分层约定、开发规范与运行入口详见 [docs/工程结构说明.md](docs/工程结构说明.md)。

## 发布

正式线上环境为 ECS 上的 Docker 容器（`docker-compose.yml`），对外由 Nginx 代理 `127.0.0.1:8015`。

两种发布通道任选其一：

1. **手动发布**：双击根目录 `deploy_cloud.bat`。脚本推送本地已提交的 `main`，再通过 SSH 让 ECS 拉取代码、构建镜像、重启并做健康检查。详见 [docs/手动部署说明.md](docs/手动部署说明.md)。
2. **CI/CD**：`push` 到 `main` 或手动触发时，`.github/workflows/ci-cd.yml` 会在 Actions 上依次执行前端/后端验证，通过后自动部署到 ECS（需配置相应 Secrets）。详见 [docs/CI-CD部署说明.md](docs/CI-CD部署说明.md)。

服务器上的 `.env`、`output/`、`logs/` 仅保留在 ECS，不会因发布被 Git 覆盖。
