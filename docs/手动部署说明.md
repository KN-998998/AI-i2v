# 手动部署说明

`deploy_cloud.bat` 是 CI/CD 的人工兜底入口，用于检查本机到 ECS 的 SSH 部署链路，或在自动部署失败后进行明确的人工排查。它不是日常首选发布方式。

> [!WARNING]
> 正常情况下只执行 `git push origin main` 并等待 CI/CD。对同一提交同时运行 Actions 部署和 `deploy_cloud.bat` 会导致重复部署与难以解释的日志。

## 脚本做什么

`deploy_cloud.bat` 会依次：

1. 检查本机 Git 与 OpenSSH Client 是否可用。
2. 检查本地部署私钥是否存在。
3. 检查是否有未提交文件，并提示“只部署已提交版本”。
4. 将本地 `main` 推送到远程（如有未推送提交）。
5. 通过 SSH 连接 ECS，在项目目录执行 `git pull --ff-only origin main`。
6. 执行 `bash scripts/deploy_server.sh`，由服务器构建并重启容器。

脚本成功只说明 SSH 链路、服务器脚本和健康检查已完成；仍应打开页面进行一次业务功能验证。

## 使用前检查

- 本地修改已提交；未提交内容不会被部署。
- Git 和 OpenSSH Client 已加入 `PATH`。
- 部署用户、项目目录、SSH 私钥路径已在脚本或本机部署配置中正确设置。
- ECS 上已有项目目录、Docker、Docker Compose 和本地 `.env`。
- 当前提交没有正在运行的 CI/CD Deploy 作业。

建议先在本地执行：

```bat
scripts\verify.bat
git status
git log -1 --oneline
```

## 执行方式

双击项目根目录的 `deploy_cloud.bat`，或在命令行执行：

```bat
deploy_cloud.bat
```

脚本窗口会保留服务器输出。看到成功提示后，再检查：

```bash
docker compose ps
docker compose logs --tail=100
curl --fail http://127.0.0.1:8015/api/config
```

上述命令应在 ECS 项目目录中执行，并由具备相应权限的运维人员操作。

## 常见问题

| 提示或现象 | 处理建议 |
| --- | --- |
| `Git was not found` | 安装 Git 或修复 `PATH` 后重新打开终端 |
| `Windows OpenSSH Client was not found` | 安装 Windows OpenSSH Client 并确认 `ssh` 可执行 |
| 找不到部署私钥 | 检查本机部署配置；不要把私钥复制进仓库 |
| `git push` 失败 | 先处理认证、网络、冲突或未提交修改 |
| ECS SSH 失败 | 检查主机可达性、端口、部署用户和公钥授权 |
| ECS 构建失败 | 查看脚本窗口与容器日志，确认磁盘、内存和 Docker 状态 |
| 健康检查失败 | 检查 `.env`、容器状态、应用日志和 Nginx 反向代理 |

## 回滚与数据保护

- 不要删除 `output/`、`.env` 或 `logs/` 来尝试恢复服务。
- 不要直接在 ECS 工作树修改和提交业务源码。
- 回滚应从本地选择已经验证的提交，经正常 Git/CI 流程重新部署。
- 若涉及运行媒体或草稿，先确认独立备份与准确目标再进行清理。
