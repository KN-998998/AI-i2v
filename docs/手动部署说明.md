# 手动发布到 ECS

当前阶段使用 `deploy_cloud.bat` 手动发布，避免每次 `git push` 自动触发 GitHub Actions 部署。

## 日常操作

1. 在本地完成代码修改并自行提交：`git add ...`、`git commit -m "..."`。
2. 双击项目根目录的 `deploy_cloud.bat`。
3. 脚本会先推送本地已提交的 `main`，再通过 SSH 让 ECS 拉取最新代码、构建镜像、重启应用并检查 `/api/config`。
4. 出现 `[OK] ECS deployment completed.` 后，浏览器刷新即可看到新版本。

本地存在未提交文件时，脚本会给出提示，但仍只发布已经提交的版本；未提交内容不会被部署。

## 前置条件

- Windows 已安装 Git 和 OpenSSH Client（`git`、`ssh` 在 PATH 中）。
- 私钥文件存在于 `%USERPROFILE%\.ssh\short-video-github-actions`。
- ECS 上使用 `deploy` 用户，项目目录为 `/opt/apps/short-video`。
- ECS 的 `.env`、`output`、`logs` 均保留在服务器上，发布过程不会覆盖它们。

## 失败排查

- `Git push failed`：先提交代码或处理 Git 提示的冲突、认证问题。
- `Deployment SSH key was not found`：检查本机部署私钥是否仍在上述路径。
- `ECS deployment failed`：查看 BAT 窗口中服务器输出。若构建阶段再次出现 `signal: killed` 或连接被关闭，当前 2 核 4G 的内存仍不足，需升级服务器或改为在 CI 构建后拉取镜像。
