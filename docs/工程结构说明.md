# 工程结构说明

本项目按运行边界拆为四个源码模块：`pipeline/` 负责可脚本化的批量生产，`web/` 只负责 FastAPI 服务与业务编排，`frontend/` 只负责 React Flow 工作台，`tests/` 集中保存自动化验证。

## 目录职责

| 目录 | 用途 | 是否提交 Git |
| --- | --- | --- |
| `pipeline/` | 图片匹配、提示词、可灵生成、审核、ffmpeg 合成、TTS | 是 |
| `web/` | HTTP API、后台任务、草稿与媒体服务 | 是 |
| `frontend/` | React、TypeScript、Vite 和前端测试 | 是 |
| `tests/` | 后端与流水线 Python 测试 | 是 |
| `scripts/` | Windows 下构建、验证等统一入口 | 是 |
| `output/` | 草稿、上传文件、片段、成片与后台任务结果 | 否 |
| `web/static/canvas-app/` | 前端构建结果，由脚本自动生成 | 否 |
| `logs/`、`.tmp/` | 日志、测试与诊断临时文件 | 否 |

## 开发约定

1. 页面与交互改动在 `frontend/src/` 完成，执行 `scripts\\build_frontend.bat` 后由 FastAPI 提供静态文件。
2. API 保持在 `web/api/`，业务逻辑放入 `web/services/`；路由层不直接承担耗时任务或文件处理细节。
3. 新增 Python 测试放在 `tests/backend/` 或 `tests/pipeline/`；前端领域模型测试放在 `frontend/src/` 并由 npm 脚本执行。
4. 密钥、素材库绝对路径、视频与生成结果仅存于 `.env` 或 `output/`，不得写入源码或提交 Git。
5. 提交前运行 `scripts\\verify.bat`。它会先生成前端静态文件，再依次执行前端模型测试和 Python 测试。

## 运行入口

- 日常开发：双击根目录 `start_dev.bat`。
- 仅构建前端：运行 `scripts\\build_frontend.bat`。
- 全量验证：运行 `scripts\\verify.bat`。

`start_dev.bat` 固定使用 `127.0.0.1:8015`，会结束该端口的旧服务并打开工作台页面。
