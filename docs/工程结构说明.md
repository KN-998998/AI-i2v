# 工程结构说明

项目按职责边界分层。`frontend/` 负责流程画布和独立操作页，`web/` 负责 FastAPI、草稿持久化与后台编排，`pipeline/` 提供可复用的媒体和模型适配能力，`tests/` 集中保存自动化验证。

## 目录职责

| 目录 | 用途 | 是否提交 Git |
| --- | --- | --- |
| `frontend/` | React、TypeScript、React Flow 页面、状态和模型测试 | 是 |
| `web/api/` | HTTP 路由、请求校验和响应映射 | 是 |
| `web/services/` | 草稿、素材库、生成、合成、图片处理和质量提示等业务服务 | 是 |
| `pipeline/` | Kling、GoodsMatting、ffmpeg、TTS、提示词等领域适配器 | 是 |
| `tests/backend/` | API、服务和状态持久化测试 | 是 |
| `tests/pipeline/` | 提示词、TTS 和媒体处理测试 | 是 |
| `scripts/` | Windows 构建/验证和 Linux 服务器部署入口 | 是 |
| `output/` | 草稿、上传媒体、片段、成片和任务记录 | 否 |
| `web/static/canvas-app/` | 由前端构建生成的静态文件 | 否 |
| `logs/`、`.tmp/` | 运行日志、测试缓存和诊断临时文件 | 否 |

## 开发约定

1. 页面和交互改动放在 `frontend/src/`。前端通过 `scripts\build_frontend.bat` 生成后由 FastAPI 提供静态文件。
2. API 路由只处理 HTTP 责任；耗时任务、文件处理和草稿状态应放在 `web/services/` 或 `pipeline/`。
3. `pipeline/` 不保存页面状态，也不直接耦合 HTTP。它只提供可被服务层调用的模型、媒体和提示词能力。
4. 新增 Python 测试放在 `tests/backend/` 或 `tests/pipeline/`；前端领域模型测试放在 `frontend/src/` 并由 npm 脚本执行。
5. 密钥、素材库绝对路径、视频和生成结果只存于 `.env` 或 `output/`，不得写入源码或提交 Git。
6. 生成任务必须在保存 `task_id` 后进入轮询状态，使服务重启后的恢复逻辑能够安全接管。
7. 提交前运行 `scripts\verify.bat`。该脚本构建前端，再运行前端模型测试和 Python 测试。

## 运行入口

- 日常开发：双击根目录 `start_dev.bat`。
- 仅构建前端：运行 `scripts\build_frontend.bat`。
- 全量验证：运行 `scripts\verify.bat`。
- ECS 手动发布：双击根目录 `deploy_cloud.bat`。

`start_dev.bat` 固定使用 `127.0.0.1:8015`，会结束该端口的旧服务并打开流程画布。构建产物和临时日志不会进入 Git。
